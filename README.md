# RH Games

Дизайн каталога, страницы игр, галереи и схема обновлений: [docs/updates.md](docs/updates.md).

Общий статический сайт «Ловца чудес» и «Храни короля». Исходные проекты остаются
в отдельных приватных репозиториях. «Морок» в этот каталог не входит.

`games.json` фиксирует версию и полный коммит каждой игры. `site/` содержит
каталог и общие стили/скрипты запуска, `templates/game.html` — общую игровую
страницу. `tools/build_site.py` экспортирует выбранные коммиты в `dist/` и
проверяет каждую контрольную сумму перед публикацией в GitHub Pages.
После проверки исходного экспорта сборщик заменяет только две HTML-страницы
запуска каждой игры и пересчитывает их контрольные суммы. PCK, движок, версии
игр и исходные релизные архивы сохраняются. Общие исправления сайта применяются
и при следующих релизах игр.
В `main` хранятся исходники сайта и список версий. Служебная ветка `deploy`
содержит последнюю готовую сборку вместе с игровыми файлами.

## Timeweb App Platform

Подключить репозиторий `rh-games-web` со следующими настройками:

| Поле | Значение |
| --- | --- |
| Тип приложения | Frontend → HTML/CSS/JS |
| Ветка | `deploy` |
| Директория проекта | Корень ветки, поле оставить пустым |
| Стартовая страница | `index.html`, определяется автоматически |

Команды сборки и запуска не нужны. В `deploy` уже находятся `index.html`,
`assets/`, `versions.json` и каталоги обеих игр. Включить автодеплой Timeweb
при обновлении выбранной ветки.

Ветка обновляется только после успешной сборки и проверки всех файлов.
При публикации её содержимое полностью заменяется последней сборкой, без
накопления истории больших бинарных файлов. Редактировать `deploy` вручную
не следует: изменения нужно вносить в `main` или в исходные проекты игр.
Маркер `.rh-games-deploy.json` фиксирует исходный коммит сайта. Повторный
запуск того же коммита не меняет ветку; конкурентное изменение защищено
`force-with-lease`. Ветка без маркера владельца автоматически не перезаписывается.
GitHub Pages продолжает публиковаться из того же проверенного артефакта.

[Документация Timeweb](https://timeweb.cloud/docs/apps/deploying-frontend-apps/static-website).

## Обновление игры

1. Обновить `VERSION.json` штатным `tools/version.py` в исходном проекте.
2. Отправить изменения и тег `v<версия>` на GitHub.
3. Workflow **Build and publish Web release** проверит проект, создаст Web ZIP
   в GitHub Release и обновит только запись этой игры в `games.json` сайта.
4. SSH push запускает **Build and publish both Web games**. Сайт заново собирает
   оба закреплённых коммита и публикует их одним завершённым артефактом.

Репозиторий сайта собирает игры из точных исходных коммитов, а не скачивает
приватные архивы по широкому личному токену. Исходные Web ZIP остаются в
GitHub Releases для скачивания. Actions Artifacts служат временными копиями.

При ошибке сборки существующий сайт продолжает работать. Одновременные
релизы сохраняют записи обеих игр; устаревшая версия не может автоматически
заменить более новую. Повторная отправка того же релиза не создаёт коммит.
Для отката владелец явно возвращает соответствующую запись `games.json`.

## iPhone и звук

Игровые файлы загружаются до активации кнопки «Играть». Сам движок и его
AudioContext запускаются по этому нажатию. При наличии Audio Session API
используется `playback`, чтобы музыка не зависела от переключателя звонка iPhone.
Громкость и отключение звука в самих играх сохраняют своё действие.

Кнопка полного экрана использует доступный Fullscreen API. Если браузер его
не предоставляет, открывается подсказка и доступен разворот внутри страницы.
Для запуска без панелей браузера на iPhone: «Поделиться» → «На экран „Домой“».
Общий manifest с относительными scope/start_url работает и под префиксом
GitHub Pages, и на отдельном домене. Офлайн-режим не заявляется.

## Доступ

- `LOVEC_SOURCE_KEY` и `HK_SOURCE_KEY` — разные read-only SSH deploy keys
  соответствующих исходных репозиториев, используются только при checkout.
- `RH_GAMES_WEB_DEPLOY_KEY` в каждой игре — отдельный SSH deploy key с записью
  только в `rh-games-web`, используется после успешной проверки Web-сборки.
- Личные OAuth/PAT-токены и Android/Telegram-секреты в сайт не передаются.
- Публикация запускается только из `main`; внешние pull request не получают ключи.

## Локальная проверка

Python 3.9+, Godot 4.7.2 stable и его Web export templates.

```sh
python3 -m unittest discover -s tools/tests -v
python3 tools/build_site.py --sources /path/to/source-checkouts
python3 -m http.server 8765 --directory dist
```

Checkout каждой игры должен совпадать с SHA в `games.json`. Для уже экспортированных
игр доступен `--from-existing`: проверка SHA и файлов всё равно обязательна.

Обе игры используют однопоточный WebGL 2 экспорт, поэтому сайту не нужны
COOP/COEP-заголовки или отдельный сервер игровой логики. Сохранения разделены
по игре в IndexedDB браузера. Очистка данных сайта удаляет прогресс; переноса
между устройствами и синхронизации с Android/Windows нет.
